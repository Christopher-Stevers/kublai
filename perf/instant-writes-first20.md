## Next source audit: openDocument saved-page read

`DocumentDrawingWorkspace.tsx:46` passes live mutation output into `useDrawingSnapshot(document-sheets:${versionId})` without localFirst or accessRevoked. The shared hook already reads that exact key online (no custom reader), but only exposes its saved value offline unless localFirst is enabled. Thus a previously materialized/downloaded version can have real saved page IDs on disk while an online cold revisit still shows “Opening drawing workspace…” until the mutation returns. No new ID is needed to improve that path. Storage is already account-bound with generation checks; the version key currently omits jobId, although saved real rows include jobId/documentVersionId/organizationId and the version UUID is a server identity. Normal DocumentDetails previews are keyed by version.id, and DrawingAccountProvider remounts the private subtree on account replacement: no unkeyed production version-switch replay is established by this audit.

`server/documents/drawing-workspace.ts` authorizes the actual document/folder ACL/recycling state before reading page rows or file bytes. Existing page rows return immediately from the server; absent rows require PDF parsing and real random UUIDs in a locked transaction, with a second access check before publication. Those missing-page identities and acceptance must stay remote. Rendering saved rows must never treat the background materialization as acknowledged or grant annotation capabilities from a stored response.

There is a concrete denial gap to fix before enabling online saved-page paint: the component never passes the mutation's denial into snapshot suppression, and its sheet-present branch does not render the error. Offline saved rows can therefore outlive a known denial from a previously started openDocument request in this component. The general tRPC denial link captures operation-start authority for imperative calls, but `reportDeviceReadDenial` explicitly accepts only reviewed **query** operations; this endpoint is a mutation. Neither its terminal failure nor arbitrary mutation refusals currently count as a read-denial purge. Child DrawingWorkspace get/changes reads have their existing denial fences; they do not justify ignoring the parent document's already-known ACL denial. Existing document viewer tests mock the store/mutation; the unauthorized test has no saved rows, so it does not prove denial-vs-snapshot behavior.

Minimal proposal, awaiting review: expose only exact already-saved rows for the currently selected account/job/version while the existing mutation revalidates; validate each saved row's real job/version/organization identity, keep offline legacy keys compatible, and add immediate per-operation account/read-authority-scoped terminal-denial suppression. A narrowly reviewed materialization-read denial classification/purge path is needed rather than globally treating mutation failures as account revocation. Capture request identity at start, fence late success/error after version/account/unmount replacement, refuse persistence after denial, and preserve the existing child authoritative capability gate. Transient failures may leave the saved read visible with a notice; missing pages remain explicitly pending. Do not prefetch another version or unopened sheets, expand neighbor behavior, fabricate page rows or change the PDF/zoom/worker/schema paths. Required proof is real-hook/disk deferred mutation tests for online saved paint, accepted replacement, transient versus terminal failure, late disk/response after denial, account/version change and imperative denial operation-start scoping. No implementation is authorized by this proposal.

The openDocument proposal above is now implemented in prepared source with the scoped proof in `document-saved-pages.md`; it remains unactivated and does not turn a saved-page read into instant materialization acceptance.
