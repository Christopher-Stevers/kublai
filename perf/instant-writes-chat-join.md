# Job chat join — bounded transport preparation

This later source slice is excluded from frozen R12. Joining remains remote work: existing Joining feedback is preserved, and only a successful authoritative overview can establish membership and unlock history/composer. No local joined flag, membership row, ID, queue or server change is introduced.

`JobChatThread` uses a narrow `useChatJoin` controller and the existing direct tRPC transport. A synchronous per-binding latch blocks same-turn auto/manual overlap. Browser connectivity, page activity, fresh overview and read authority are checked again immediately before dispatch. There is no TanStack paused mutation or reconnect replay, and no retry loop. The existing server still locks the job, inserts membership with `onConflictDoNothing`, and returns the authoritative overview.

A confirmed join does not wait on overview invalidation. If its ACK arrives offline, Joining releases without claiming fresh membership or starting another read. Existing active/reconnect overview refresh and its nonmanual authority certificate still gate history/composer. An uncertain transport outcome checks current membership before any explicit new join; failed/timed-out checking changes the button to Check membership rather than resending. The read wait is bounded at 15 seconds and canceled on Activity hide/unmount/binding replacement. An already dispatched authorized request is not canceled or undone.

Pending/check state and the synchronous latch are bound to identity plus captured read authority. New bindings can start independently; old completions cannot update error UI or clear a newer request's lock. Activity uses a separate lifecycle epoch. These are client callback/admission fences; this slice does not add an actor guard to the existing chat server input or change request authentication.
