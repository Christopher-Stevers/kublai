# Device read cache authority

Reviewed reads may keep acknowledged data for an authenticated account. Writes in flight, mutation errors, private HTML, and unreviewed procedures are excluded. The v2 query envelope serializes each query once, retains the newest eligible queries and preserves SuperJSON dates. The total serialized Tier 1 payload allowance is 20 MiB: the query envelope now reserves 256 KiB for the separately bounded receiving summaries. Browser/IndexedDB metadata overhead is not included in this payload measure.

A structured UNAUTHORIZED, FORBIDDEN, SIGNED_OUT, NOT_FOUND, or HTTP 401/403/404/410 from a reviewed authority read locks the saved workspace and clears its query memory and saved query record. Authority reads include the persistence allowlist plus `drawingsWorkspace.get`, `list`, and `changes`; the latter three do not become persisted queries. The client transport reports raw tRPC reads as well as TanStack-managed reads. A request captures its current authority token, so an old account's late refusal cannot revoke a newer session. Mutation refusals and ordinary network failures do not trigger this policy.

The reviewed `materialList.getOrderById` read has a narrow exception: a missing order (NOT_FOUND/404/410) revokes only its captured protected snapshot key. It does not purge unrelated account data. Its explicit expected-account mismatch suppresses that view without purging another account. The raw response is never persisted; only the dated, read-only projection described in [receiving-saved-order.md](receiving-saved-order.md) is eligible. Identity denials still use the existing operation-start account fence. Durable per-order deletion cannot be guaranteed while storage is unavailable; the affected reader suppresses saved paint and keeps uncached live reads available for operational storage failures.

Drawing-related denial conservatively purges the account's separate saved snapshots, downloaded assets, and kept PDFs. A deleted asset read does not purge unrelated drawings. Ordinary account switching retains allowed downloads. Disk writes compare their captured persistent revocation generation in the same IndexedDB write transaction; deleting data advances that generation. An old tab cannot repopulate a cleared record merely because its storage event was delayed. Fresh validated bindings capture the new generation. A synchronous denial marker and existing cross-tab lock signal cover pending purge/reload; the transaction fence supplies the durable late-write guarantee. Failed purges retain the denial marker for retry.

This reacts to authoritative refusals encountered by these reviewed read paths and existing service-worker navigation checks. It is not a complete subscription to every job-membership or role change, and it does not reinterpret arbitrary endpoint errors as revocation. The locked screen asks to refresh the workspace, without asserting that an account changed.

Focused tests cover strict byte cap and recency, nested SuperJSON dates, optimistic pending exclusion, offline reuse, mutation refusal, delayed query saves, independent-context drawing writes without storage-event delivery, stale revocation against a fresh query generation, reload recovery, and stale async account binding.

A local synthetic microbenchmark (`pnpm exec tsx scripts/benchmark-device-query-cache.ts 160 8192`, three same-process samples per size) measured median encode time at 40/80/160 queries as 14.96/62.83/280.70 ms for the previous cumulative serialization and 0.67/1.36/2.77 ms for the entry codec. The largest encoded payload was 1,398,304 bytes. These are host microbenchmarks, not phone INP or accepted journey measurements.
