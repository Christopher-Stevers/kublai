# Shared scale ACK hardening — prepared source

This slice preserves calibration's existing immediate draft and Saving scale feedback. The engineering scale and its revision remain authoritative server results. It is not an optimistic calibration, a same-frame acceptance claim, a measured speed gate, or a canonical build/activation.

Ordinary `DrawingWorkspace` calibration uses `useDrawingScaleSave`: a synchronous per-sheet latch, actual online admission checked again at dispatch, `networkMode: always`, and no retry or durable queue. The additive optional `expectedAccountKey` is compared with the effective organization/user/simulation scope before the existing scale service; legacy callers may omit it. Existing sheet locking, annotation permission and revision allocation remain in that service.

A real ACK can finish without waiting for query cancellation or background refresh. Only existing cache rows are reconciled, without copying capabilities from the proposal. Actor binding/read authority fences prevent old-account reconciliation. Same-account reconciliation survives view removal, while source/sheet/Activity ownership separately fences UI completion. Both query metadata and accepted local metadata revisions can veto an older ACK. Viewer receives the real accepted scale plus permission to finish this view; a stale ACK cannot install the proposed scale into a resumed measurement. Existing boolean/void callbacks remain compatible.

Refusals retain calibration points and text. A transport failure may have lost an ACK after acceptance: it asks the user to refresh/check the latest scale before another proposal, rather than claiming the write definitely failed. There is no automatic resend. The existing Super scale metadata-save route remains unchanged, as do measurement geometry, zoom, source-override eligibility, offline private-edit queues and already-authorized work.
