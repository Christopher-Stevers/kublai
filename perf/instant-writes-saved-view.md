# Existing private saved-view name — scoped immediate write

Prepared source only, excluded from the frozen R6 candidate. This is one caller slice of `drawingsWorkspace.save` (67 seven-day observed procedure calls, including other drawing actions and possibly QA). The journal does not count saved-view renames separately. It is not completion of the first twenty writes or proof of physical-frame latency.

Only an existing own private `view` entity with a positive expected revision is eligible. Source sheet, center and zoom must match the cached entity exactly; name is the only changed data field. Create, public/share, geometry, version, review, transmittal and deletion remain on their existing paths. The existing drawing durable queue is unchanged. Catalogue name-only editing was rejected here because its surviving list is Replicache-backed and has no rename mutator or existing name overlay; changing a closing detail dialog would not meet the visible-result goal.

The typed query transaction changes the workspace's entity name in the initiating call; the matching form closes and the surviving selected title/list shows the pending name. The authoritative response supplies the real entity revision. A refusal rolls back only the owned query/value and restores the submitted name draft without replacing another open form. A later server response, query eviction, account wipe or authority change wins. A synchronous pending-entity guard consumes repeated submissions before they can fall through to legacy save. Offline submissions do not queue or retry.

Cache settlement uses captured account/read-authority ownership independently of mounted UI: Activity hide/unmount must still reconcile or roll back the query, while form callbacks remain fenced by mounted sheet generation. The existing server `expectedUserId` check precedes drawing DB work; sheet authorization/ownership/revision checks remain authoritative. The mounted SimulationProvider adds the existing account-view header to same-origin API fetches; server assertSimulationView refuses changed sessions. This slice adds no server schema or permission system.

The existing workspace snapshot merge now checks stable query/value ownership and the shared pending marker both before starting its asynchronous disk read and immediately before saving. Thus an ephemeral rename cannot become a saved snapshot simply because the mutation settles or an older disk read completes. Normal authoritative workspace snapshots remain eligible; the durable queue stores its own edits as before.

Focused verification covers actual DrawingWorkspace selected/list title change after form close while network is pending, refused draft restoration, newer revision preservation, delayed snapshot completion after refusal/new authority/account removal, hook Activity hide/unmount with accepted/refused outcomes, account wipe, overlap, offline rejection and unchanged eligibility boundaries. Renderer/transport/disk are mocked in UI tests; the workspace component, form, query observer and optimistic mutation/cache machinery are real. Existing offline-queue tests run separately. These are deterministic behavior tests, not real storage quota, browser timing, production auth or multi-client convergence proof.

Final focused run: **122 unique tests passed** in three files with one Vitest worker (workspace 100, new hook 10, existing offline queue 12). New hook/tests pass ESLint with zero warnings. Existing workspace source has two errors/five warnings and its older test fixture fifty errors; all match committed HEAD exactly by rule, message and severity, with no new lint findings. No canonical build, activation, phone workload or timing capture was performed for this slice.
