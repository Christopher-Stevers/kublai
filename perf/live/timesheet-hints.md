# Timesheet read invalidations — zero polls removed

This prepared slice adds only a content-free timesheet topic to the existing shared live client/stream and PostgreSQL hint bridge. It adds no browser connection class, server reconciliation poll, schema, worker executable/service or production database operation. It is outside frozen R12 and has not been canonically built or activated.

Eight web mutation producers share the router's existing durable `event(tx, ...)` helper: `saveEntry`, `deleteEntry`, `submit`, `withdraw`, `review`, `settings`, `clockStart`, `clockAction`. After the event insert, the same transaction executes `pg_notify` on the existing channel with a bounded hint. PostgreSQL publishes only after commit. A transaction failure rolls back the notification with the write; a refused/no-op command reaches neither. An accepted settings update advances its revision even if values match, so it remains an actual revision-changing producer rather than a suppressed no-op.

Personal hints stay within the effective user's organization and reach that user or an authorized manager; settings changes use an organization audience. Audience IDs remain server-side. The browser frame contains only topic/version/kind, not employee/sheet/timer IDs, notes, totals, capability values or timestamps. Simulated sessions retain their full separately authenticated account scope and effective-user audience. Requesting this Dev-only topic requires the existing timesheets tab permission and app/organization access. HTTP reads/mutations retain all existing authorization; hints grant nothing.

`TimesheetsView` subscribes only after its context identifies the bound effective user. Active hints, stream catch-up/reset and LISTEN re-establishment coalesce into authoritative active-query invalidation through existing query utilities. Hook cleanup, account/read-authority changes, hidden/inactive/offline states suppress delayed callbacks. Query failures do not grant authority. Existing shared transport handles reconnect/backoff, hiding, account boundaries and the four-minute source reauthentication lifetime; no parallel timesheet EventSource is created.

The **30-second `timesheets.context` poll remains exactly unchanged**. It also supplies organization jobs/people, editing/management/configuration permissions and timezone-based today; timesheet writes do not cover those independent producers or midnight. Therefore this slice removes **zero poll declarations** and does not satisfy a no-poll gate. It improves event-driven freshness of detail/list/report/activity/context reads without weakening the existing broad authority fallback. Full producer/authority coverage would be needed before any future removal.

The original revision remains intact. The wrapper creates only a synthetic Unix-socket cluster, exits successfully and cleans it up. No production database is touched.
