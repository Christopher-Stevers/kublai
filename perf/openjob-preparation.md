# Open-job preparation: remove one discarded local query

The R17 source audit found `journeyRegistry.openjob.data → jobData → rep.query(readJobDetail(tx, jobId, false))`. The query reads the job plus the `listsByJob` index; its result is discarded. `prepareJourney` returns only settled preparation and does not publish that value to a React/query/shared reader cache. The actual options screen continues to read through `JobsClient → useReplicacheJobDetail(jobId, false) → createSharedReplicacheReader → rep.subscribe(readJobDetail)`, initially rendering the existing jobs-list fallback. Any internal storage warming is distinct from an application result handoff; removing the speculative read does not change the live subscription or permission authority.

Only `openjob.data` changes to the existing `noData` callback. Its code prewarm remains intact. `switchjobtabs`, drawing preparation, list preparation and all workspace-option consumers retain their existing data work. The change introduces no cache, write, permission grant, new navigation behavior, Activity/ref memoization or mutation of the frozen lab method.

Six focused registry tests pass: route mapping; canceled open-job preparation skips module/data work; code preparation occurs once while repeated open-job preparation performs no query; the unchanged switch-tab path still reads lightweight job metadata; cancellation still suppresses its data reads; chat preparation remains read/write free. Scoped ESLint passes, with the existing mock callback given an explicit safe type. No browser, DB, benchmark, typecheck or build was run for this patch.

This source-derived redundant-work removal is prepared outside frozen R17 and the separate three-chunk experiment. It does not establish the cause of the retained R17 Site/Office open-job regression or claim a latency/byte improvement.
