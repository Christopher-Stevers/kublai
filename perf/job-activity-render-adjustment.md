# Transactional retained-panel bookkeeping

`JobActivityPanels` previously committed the active child, then updated its retained-node array from a layout effect. A fresh child ReactNode on a parent render changed that array even when the active key stayed the same, causing a second bookkeeping commit. The active child was already sourced from props, so the second commit did not need to publish new content.

The bounded replacement computes the same three-panel array and conditionally adjusts this component's own state during rendering only when length/key/node identity differs. Stable props on React's immediate retry satisfy the equality guard. It creates no side effects, mutates no array/ref/external state during render, and keeps the previous active node in the next retained array during a key transition. State remains part of React's render transaction rather than a ref that could expose speculative children. This follows the documented [conditional previous-render state adjustment pattern](https://react.dev/reference/react/useState#storing-information-from-previous-renders). The setter is not unconditional; no parent state is changed.

Validation: 11 focused tests across `JobActivityPanels.test.tsx` and the existing `JobsClient.activity.test.tsx` pass, with scoped ESLint clean. Coverage includes active DOM identity and draft preservation across fresh ReactNodes in Strict Mode; hidden effects disconnect/reconnect; bounded eviction; job/account key reset; no unopened panels; paused authorized mutation completion; and an abandoned suspended transition that cannot retain its speculative panel. JobsClient integration continues to retain reviewed views and unmount excluded editors.

A Profiler regression asserts exactly one `update` commit for fresh active child props. Running that test against the prior actual production component failed with `['update', 'nested-update']`; restoring this patch passed. This establishes removal of the tested post-commit bookkeeping update, not an amount of production CPU/frame/latency improvement or the cause of the retained Site/Office open-job failures. Suspense/Strict Mode tests provide bounded concurrency coverage, not a proof of every possible scheduler interleaving.

No Jobs-root retention, refs-only cache, child field/permission semantics, frozen R17 source, timing adapter, threshold or baseline changed. This patch is a later candidate only. No DB, browser, build, full benchmark or typecheck ran for this change; no further runtime measurement is queued.
