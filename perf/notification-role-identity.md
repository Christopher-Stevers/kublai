# Notification identity sharing (prepared source)

NotificationCenter may reuse a fresh `user.getMyRole` HTTP response only inside a validated drawing account binding. The server returns the existing `notificationAccount(ctx.user)` result directly, alongside effective user, organization, actor and simulation fields. Its stricter approved-status/dashboard permission checks remain independent of legacy role `appAccess`; scope strings are never parsed.

The passive receipt hook adds no role query, observer or polling timer. It observes an enabled existing owner (`Query.isActive()`), fetch start and nonmanual completion after mount; verifies account, actor, simulation, browser view and current device-read generation; and expires shared authority at most 30 seconds from request start. One expiry deadline restores fallback; every render also checks current wall time so a throttled deadline cannot extend authority. Null is a certified denial, not a reason to use stale standalone data.

Missing/disabled owner, error, manual cache replacement, expiry, lifecycle or binding change restores the existing standalone identity query. After shared ownership, an older standalone response cannot reappear: recovery needs a later observed HTTP completion. Explicit refresh resets the receipt before a post-commit standalone refetch. A once-per-binding/barrier recovery also refetches the already-enabled standalone query after lifecycle or authority loss; it waits while hidden/offline and does not recursively retry observed standalone errors or malformed successes; those remain denied until a normal interval or explicit recovery attempt. If recovery joined a pre-binding request, that unobserved completion cannot certify identity and instead enables exactly one fresh recovery attempt. Inbox/list polling and server account assertions are unchanged. Push identity, its physical-actor/VAPID rules and all frozen candidates are excluded.
