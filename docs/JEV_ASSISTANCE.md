# AI assistance workspace retired

On 2026-10-10, Tim requested removal of all six AI assistance tools: material finding, supplier matching, catalogue organization, material-list checks, drawing classification and room-outline review.

Their interface, entry links, API router, TypeSafe client, cache, PDF text worker and dedicated tests have been removed. Old `/dashboard/assist` bookmarks redirect to Jobs. No database migration is required; these tools did not persist changes. Existing room detection and normal catalogue, supplier, material-list and drawing tools remain independent.

The application no longer reads TypeSafe environment settings for this workspace. The project TypeSafe skill remains available for any future explicitly requested integration.

## Packing-slip receiving review (2026-10-17)

The retired assistance workspace remains removed. A separate, narrowly scoped packing-slip review now uses TypeSafe after a linked slip is saved.

- Server-only `TYPESAFE_API_KEY` enables `jev-latest` at the official System One endpoint. The browser never receives credentials.
- Scanned pages are read locally with Tesseract (English data required). PDFs render in a bounded child process using the existing PDF.js/canvas dependencies. Up to 20 pages and 150 text rows are analyzed; omitted/unreadable pages and rows are reported.
- The service sends recognized text, table positions, and candidate order descriptions/SKUs/aliases to TypeSafe. Choice answers select existing numeric spans and candidate items; model-generated quantities are never used. Exact SKU and explicit column matches use code. Unclear quantities, ambiguous units, duplicate lines, and nonmatching items stay flagged rather than being filled in.
- All quantities are proposals. The user checks the physical delivery and confirms received quantities. Confirmed amounts add to earlier receipts; a transaction rechecks permissions, document version, current order contents and existing received quantities. A persisted application receipt prevents repeated submissions from counting the same document twice. A fresh photograph of an already received physical slip is not reliably recognized as a duplicate; prior receipt totals and a warning remain visible.
- Receipt analysis and confirmation evidence live on the linked document in the existing job-document workspace. PDF saving succeeds independently of analysis. Failed/interrupted runs can be retried; manual verification remains available.
- Runtime jobs are serialized and bounded in the application process. An interrupted processing lease can be retried after 15 minutes. This is not a durable external worker queue.

Validation: isolated PostgreSQL tests cover confirmation/idempotency/conflicts/permissions. A synthetic scanned PDF was read with real Tesseract and the configured TypeSafe service: 6 shipped/4 backordered and 8 shipped/0 backordered matched the test order; an unordered extra item was flagged. This fixture verifies the integration, not general accuracy on supplier documents.

## Job specification assessment (2026-10-20)

The job **Systems** page now provides a separate, explicitly requested assessment of selected job documents and drawing sets. The source picker defaults to **Documents → Specifications** and remembers the last assessment selection. It uses the existing server-only TypeSafe key and System One endpoint. Local text/OCR extraction produces source-bound passages; typed questions select supported system, material, size-range, qualifier and joining candidates. Drawing notes, schedules and legends provide candidate systems, with an explicit applicability review issue; image-only drawing symbols need manual review. The original document/version/page/section or drawing sheet/revision evidence remains accessible in review. Results constrain drawing takeoff only after rule review and any required material-choice/catalog mapping.

Assessment is on demand, never triggered by ordinary document upload/viewing. Unsupported, contradictory, ambiguous and incomplete requirements remain review issues. User corrections and selections survive reassessment. Tenant/folder permissions and immutable source versions are checked before assessment and again at commit. Bounded background processing persists progress and exposes retry after interruption; there is no external worker queue.

See [Job systems](JOB_SYSTEMS.md) for supported formats, bounds, setup, privacy and tests. A synthetic PDF was tested through real local extraction and the configured `jev-1.13.0` service: it returned the expected copper-at-or-below-2-inch / carbon-steel-above-2-inch rules, plus fittings, bronze ball valves and threaded joining. No customer documents were sent for that test. This validates connectivity and the synthetic workflow, not real specification accuracy.

## Production packing-slip cascade (2026-10-27)

The app uses its normal OCR/table parser, then the existing Jev image pipeline when deterministic parsing is insufficient. It calls `gpt-6.1-terra` at medium reasoning only if the remaining reading has unresolved order identity, unreadable rows/quantities, uncertain products, or coverage/totals conflicts. Confidence cutoffs reuse provisional Jev checks; they are not calibrated accuracy claims. Missing printed units, duplicate receipt decisions, handwriting disposition and returns still require a person. A clear reading does not call Terra. Running Terra on all documents remains a separate, explicitly started development evaluation.

Server-only configuration: `OPENAI_API_KEY`, `PACKING_SLIP_TERRA_ENABLED=true`, and a comma-separated `PACKING_SLIP_TERRA_ORGANIZATIONS` allowlist. Default daily guards are `PACKING_SLIP_TERRA_DAILY_USD=5` and `PACKING_SLIP_TERRA_DAILY_CALLS=50`, reset at UTC midnight. Zero disables spending. Migration `0098_packing_slip_terra_calls.sql` must be applied before enabling. A database lock reserves US$1 before each bounded request, releases the difference after reported usage, and retains the reservation for unknown costs. This conservative app guard does not govern other uses of the API key or provider billing adjustments. Limits are 20 images resized within 1600×1600, 120 KB of context, 16K output tokens, five minutes, and a 2 MB streamed response. There are no automatic Terra retries. The durable run ID reuses a completed request only for the identical source/job/context; uncertain attempts require manual review or an explicit new detection run.

Terra receives source pages, prior OCR/Jev predictions, reasons for escalation, and current-job candidate orders with received totals excluded. It may abstain or transcribe new products. Candidate lists exceeding the limit use the earlier shortlist, marked incomplete. IDs and image bounds are checked locally. Clear cheap readings are retained; changed, new or ambiguously aligned lines stay flagged. Model confidence never posts receipts. Existing duplicate checks, job permissions, source-version checks, review corrections and return approvals remain authoritative. Provider/budget failures preserve the earlier reading.

The Receiving review shows the source reader and product/quantity confidence per line. A line is automatically confirmed when any single saved reader has both part-match and quantity confidence of at least 0.90 for the displayed order item and converted quantity. This is recalculated for existing slips without new inference, only against the current source version and analysis run; human edits, excluded lines and posted receipts are preserved. Automatic confirmation does not set human-reviewed flags or post quantities: Review & Approve, duplicate checks and explicit over-delivery approval still apply. Its Detection and source text section shows escalation reasons and estimated Terra cost. Private `.review-evidence/<organization>/<analysis-run>.json` records OCR stages, Jev calls, routing decisions, Terra request/response, source image hashes, model/version, token usage and costs. Original predictions and subsequent human corrections remain separate in receiving history; only human-verified examples can become evaluation labels. No model is automatically trained or promoted by saving these records. The four-reader development comparison remains unchanged.

Pricing estimates use [Jev's published pricing](https://typesafe.ai/blog/introducing-system-one-models-and-jev) and [GPT-6.1 Terra pricing](https://developers.openai.com/api/docs/models/gpt-6.1-terra), checked 2026-10-27. Unknown usage stays unknown. Tests cover routing, provider failure, foreign IDs, signed quantities, ambiguous row alignment, budget reservations and replay protection. A real API call correctly read the synthetic 6-shipped/4-backordered fixture at an estimated US$0.003392; this verifies integration, not field accuracy.
