# Complete room detection: model and data decision

Checked against primary repositories, model configurations and dataset terms on 2026-09-30. Recommendations below are engineering judgments, not measured model accuracy. No customer drawing was uploaded to a provider, no paid inference was called, and no neural checkpoint was deployed during this investigation.

## Decision

Keep independent geometric discovery as the fast, reviewable baseline. The next serious accuracy experiment should be **local, tiled wall / opening / interior segmentation feeding the existing global polygon extraction**, rather than replacing the app with a general vision-language model. Train and evaluate it using commercially usable MSD geometry and explicitly reviewed real construction sheets. Test a promptable model separately for tap-to-add missing rooms. Direct polygon transformers are credible challengers once their training-data provenance, resolution and output capacity fit the task.

The immediate blocker to a defensible “every room” claim is complete reference annotation on actual sheets. Accepting existing proposals cannot reveal rooms that were never proposed. A larger model cannot remove that measurement problem.

## What the current evidence establishes

- Frozen, site-separated, text-free MSD holdout: 120 layouts, 3,525 interior spaces; recall 92.85%, precision 92.38%, F1 92.61% at IoU 0.5 and 0.75; 252 misses, 270 extra candidates, no detected merge/split failures or worker failures. These are the parent run's reported results; retain its run report and source hashes as the authoritative record. Do not retune against this holdout.
- `build_msd.py` draws closed, four-pixel boundaries directly from reference room polygons. This measures geometry recovery without text seeds. It does **not** measure recognition of doors, fixtures, dimensions, hatching, scanned text or unknown room names on construction documents.
- The inspected downloaded MSD JSON example contains 87 faces, all room/area entities. It has no genuine wall, door or window entities to render. Deriving such labels from room edges is a synthetic approximation. The [MSD JSON release](https://zenodo.org/records/17294451) supplies geometry and graphs under CC BY 4.0; preserve attribution and transformation provenance.
- The actual A511 label probe found 53 current room seeds, including **20 apartment occupancy descriptions** such as `2 BEDROOM` and `1 BEDROOM-BF`. The other 33 are possible physical-space labels. Rejected-label counts therefore cannot stand in for missed-room counts. Numeric occupancy descriptions should be unit context, while `BEDROOM 2` can be a physical room name. Independent walls must still discover unnamed bedrooms.
- On A511, the initial composite raster experiment produced 128 proposals, 98 unnamed. After excluding numeric occupancy descriptions from physical anchors, it still produced 128 proposals, now 12 named and 116 unnamed, with 19 rejected physical anchors. Raw vectors produced 1,086 and graded vectors 438, with fixture artifacts; neither is an established improvement. These diagnostic counts have no ground-truth precision/recall attached. Visual review found room merges at gray walls/door portals and false partitions at red revision clouds.

The existing vector extractor already retains stroke width, dash, fill, layer and door-arc evidence. Rendering without glyphs still retains vectorized text, furniture, hatch boundaries and sheet frames. More aggressive global gap closing trades missed enclosures for invented divisions; using those vector features as model inputs and repair constraints is more promising than another unrestricted closing pass.

The architecture supports localization and augmentation; its medical-image results are not floor-plan evidence. [Original paper](https://arxiv.org/abs/1505.04597). | First training experiment. Start with random weights to keep provenance simple; add an appropriately licensed pretrained encoder only after a comparison. |

## Implementable learning experiment

1. **Targets and annotation policy.** Keep corridors, lobbies, stair enclosures, elevators, closets and connected common areas; retain polygon holes. Define how to treat shafts, parking, outside balconies and open living/dining areas before scoring. A door does not merge its adjoining rooms. A unit-description anchor does not create a physical room.
2. **Training data.** Split by project/site before rendering, augmentation or tiling. Use a separate training subset of MSD; the tested development and holdout sites must not become training examples. Randomize wall thickness, rotations, door gaps, fills, fixture symbols, text, grids, dimensions, contrast and scanning noise, while keeping the clean structural target. Then fine-tune on reviewed actual sheet crops. Synthetic closed outlines alone cannot teach which real ink is a fixture.
3. **Model and loss.** Start with a compact encoder/decoder, 512-pixel tiles and overlapping context. Predict interior, walls, opening closures and nonstructural/background pixels. Use masked class-balanced cross entropy plus Dice; compare a topology loss only as an ablation. [clDice](https://github.com/jocpae/clDice) offers a connectivity-oriented loss for network structures, but its published domain is not room detection and it does not guarantee correct rooms.
4. **Recover global geometry.** Blend tile probabilities into page coordinates, then repair only plausible openings and run global component/polygon extraction. Do not concatenate independent tile room lists: corridors crossing tiles would split. Keep a low-resolution whole-sheet envelope/context path, and preserve native vector geometry for final snapping. Export provisional polygons with model/version/input-hash metadata and retained holes.
5. **Hardware proof.** The machine has an RTX 5060 Ti with 16,311 MiB VRAM and driver 610.57.04. The implemented 1.964M-parameter, 512-pixel model actually trained eight epochs with mixed precision and batch two in 108.5 seconds, using 980.5 MiB peak CUDA allocation. The isolated runtime is PyTorch 2.12.0+cu130. This proves local feasibility, not drawing accuracy. Old CUDA 11.x setup recipes are unsuitable: [PyTorch 2.7 introduced Blackwell/CUDA 12.8 support](https://pytorch.org/blog/pytorch-2-7/); current [PyTorch 2.12 guidance](https://pytorch.org/blog/pytorch-2-12-release-blog/) moves newer GPUs toward CUDA 13 wheels. See the measured pilot report for exact hashes, comparisons and actual-sheet failure.
6. **Serving.** Keep training offline and inference in a separate local worker. Use explicit GPU admission, deadline, status and fallback to geometry. CPU cgroups do not bound GPU memory. Compare model-only, geometry-only and combined proposals before enabling the model by default. Save checkpoints and manifests with checksums; never replace a live model merely because training loss decreased.

## Feedback that can actually improve completeness

Persist the original proposal, approval/rejection, corrected polygon, exact drawing hash, detector version and eventual outcome. Reruns must preserve accepted/manual rooms and avoid recreating equivalent rejected proposals. The current proposal-memory and review-priority model are useful immediately; they are not a trained wall segmenter or calibrated probability of correctness.

Manual added/traced rooms are positive examples of **misses** and must be exported. A rejected outline could be a merged pair or an incorrect boundary, so do not label its entire interior as background. Distinguish not-a-room, merge, split and boundary errors where possible. Unreviewed pixels remain unknown. Dense supervision requires an explicit human check that all spaces on that floor were considered; merely having no pending proposals is insufficient. Edited drawings invalidate that completeness check.

Build the next real-sheet benchmark from completely annotated floors across several projects/drawing styles, retaining difficult halls, small spaces and sheets with no usable text. Keep whole projects unseen. Report per-space recall, false positives per sheet, IoU at 0.5/0.75, corridor recall, small-space recall, merge/split failures, **fraction of entire floors with zero missed spaces**, review time, latency and worker failures. At 92.85% aggregate recall, even high average overlap does not support “every room.” Promote a challenger only when it improves held-out real-sheet recall without increasing false-room burden or losing previously correct spaces.
